## 6. 함정·주의

### 6.1 OneDrive 잔재 폴더
`C:\Users\oddsk\Downloads\OneDrive\문서\recipesss`가 남아있을 수도 있음. **무시**. 정본은 `C:\dev\recipesss`. 만약 어쩌다 그쪽에서 작업하면 git이 OneDrive 폴더에 push하니까 헷갈리지 마라.

### 6.2 작업 경로
이 세션은 처음부터 `C:\dev\recipesss`에서 시작했을 거. `pwd` 확인. OneDrive 폴더면 호두님께 알리고 새 세션 안내.

### 6.3 mirror 종료 (DL-021)
운영관리앱 코드를 자꾸 참조하는 습관 X. 단계 0에서 mirror는 끝. 이제 운영관리앱은 **참고만** — 자동 동기화 X.

### 6.4 데이터 안전
- `backups/2026-06-03-pre-rewrite.json` 절대 건드리지 마라. v2 마지막 스냅샷.
- 구 recipesss Firebase(`recipeee-da9d3`)는 **읽기 전용**. 절대 쓰지 마라 (DL-019).
- 새 큰 작업 직전엔 `backups/<날짜>-<사유>.json` 추가하고 commit.

### 6.5 푸시 = recipes 컬렉션에 직접 쓰기
`recipes` 컬렉션은 생산관리앱이 정식 소유. recipesss는 "등록" 액션 때만 씀. 다른 `recipes/{id}` 문서 절대 건드리지 마라. 출처 식별: `source: 'recipesss'` + `recipesssDraftId`.

### 6.6 영양제 제외 로직
`draftToRecipe` 변환 함수가 영양제(kind === 'supplement') 행을 자동 제외. **이 로직 절대 빠뜨리지 마라**. SPEC §6.5에 명시.

### 6.7 Firebase IAM
fant-e5ae5는 새 Cloud Function 배포 시 IAM 자동 부여 안 됨. MVP에 Functions 없으니 N/A. 후속 단계에서 surfacing.

### 6.8 단가 인터페이스
`/prices` 페이지는 **placeholder 유지**. 데이터 인터페이스는 단계 5에서 생산관리앱과 협의 후 결정. 원료 마스터에 단가 컬럼 합치지 마라 (DL-024).

### 6.9 운영관리앱·생산관리앱 위치
- 운영관리앱: `C:\dev\fantapet-inventory` (확정)
- 생산관리앱: `C:\Users\oddsk\Downloads\OneDrive\문서\fant management\fant` 또는 `C:\dev\fant-production` (호두님이 옮겼는지 확인)

### 6.10 `.env.local`
`C:\dev\recipesss\.env.local`에 Firebase 키 박혀 있음. `.gitignore`에 의해 commit 안 됨. 절대 commit하지 마라.
