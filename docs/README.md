# docs/

단계별 Codex 핸드오프 + 보조 문서. **정본은 `../SPEC.md`**.

## 파일 명명 규칙

```
Codex지시서_StepN-X_<주제>_<YYYY-MM-DD>.md
```

예시:
- `Codex지시서_Step0_인프라골격_2026-06-04.md`
- `Codex지시서_Step0.5-A_v2v3마이그레이션_2026-06-15.md`
- `Codex지시서_Step1-A_영양엔진코어_2026-07-01.md`
- `Codex지시서_Step1-B_AAFCO프로파일적재_2026-07-03.md`

패치/수정본은:
```
Codex지시서_StepN-X_<주제>패치<순번>_<YYYY-MM-DD>.md
```

## 각 지시서 표준 구조

1. **작업 목적** — 한 단락. 이 단계 끝에 보이는 모습.
2. **변경 대상** — 수정 / 수정 금지 명확히
3. **새 구조** — 코드 골격(필요 시)
4. **검증 기준** — 호두님 OK 받기 전 충족할 것
5. **의존** — 선행 / 다음

## 운영 원칙

- SPEC.md와 충돌 시 SPEC.md가 정본. 지시서를 패치.
- 지시서 끝나면 status를 SPEC §12에 반영.
- Codex가 작업하는 동안 Claude는 다른 단계 지시서 작성·검토 가능.
