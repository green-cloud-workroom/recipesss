### ② 프리셋 재설계 (방향 확정됨 — 지시서 작성)
**문제**: `/presets` 별도 페이지(0.5-D/E/F/G)가 호두님 실제 워크플로우(v2)와 어긋나 "꼬임"(코드·생산단위 뒤섞임). 호두님: **v2 방식으로 회귀**.

**확정 결정**:
- **`/presets` 메뉴·페이지 제거.** 레시피 목록(`/recipes`)에서 레시피 클릭 → **그 화면에서 프리셋 설정** (v2 결과 탭 방식).
- 화면: 생산단위 원료 select + **생산량 입력** → 프리셋 저장 + 저장된 프리셋 칩(20/40/60…).
- **자동 코드**: 한 레시피의 프리셋을 `targetWeight` **작은 것부터 X0·X1·X2…** (prefix는 레시피별 1글자).
- **범위 = 최소**: 구성원료 계산표·원가·영양 매트릭스는 1-D로 분리. 이번엔 프리셋 저장/목록/자동코드까지.
- **기존 프리셋(마이그레이션 100개) 유지 + 자동 재코딩**(targetWeight 크기순).
- **SPEC DL-024/DL-026 개정** 필요(프리셋 설정 별도 페이지 → 레시피 화면 통합).

**v2 계산식** (`archive/old/v2-source/modules/selectors.js` `getRatioInfo` L90-110):
```
unitRow = composition에서 unitIngredientId 원료 (unitRow.weight = 레시피기준 그 원료 g)
unitLabel = product.unitLabel (마리/개), 단 unitIngredientId가 레시피 단위원료일 때만
raw = 생산량 입력값
targetWeight = unitLabel ? raw * unitRow.weight       // 마리/개: raw마리 × 1마리당 weight
             : unitRow.unit === 'kg' ? raw*1000 : raw  // 단위없으면 g(또는 kg→g)
ratio = targetWeight / unitRow.weight                  // 모든 원료 × ratio
inputAmount = raw, inputUnitLabel = unitLabel || unitRow.unit || 'g'
```
- 순수함수로 포팅: `presetCodes.ts`에 **`normalizePresetCodes(presets, draftId)`** 추가(v2 `preset-codes.js` `computeNormalizedPresets` = targetWeight 크기순 suffix 재할당, 0.5-F에서 미룬 것). 저장/삭제 시 호출 → batch write.
- 생산량→targetWeight 계산도 순수함수 + 테스트.
- 현재 자산 재활용: `presetQueries`/`presetMutations`/`presetCodes`(0.5-F `generatePresetCode`)/`presetSelectors`. `PresetsPage.tsx`는 화면 통합으로 흡수·제거.
