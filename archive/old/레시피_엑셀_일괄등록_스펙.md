# 레시피 엑셀 일괄 등록 스펙

## 목적

레시피를 앱 화면에서 제품별로 하나씩 입력하는 부담을 줄이기 위해, 기존 엑셀 레시피 파일을 업로드하면 제품/원료/영양제 데이터를 자동으로 등록한다.

## 지원 파일

- `.xlsx`
- `.xls`

현재 구현은 첫 번째 시트만 읽는다.

## 지원 엑셀 구조

`레시피-고양이.xlsx` 샘플 기준 구조를 지원한다.

- 레시피는 가로 방향으로 4열 단위 반복
- 각 제품 블록의 시작 열은 `A`, `E`, `I`, `M` ... 순서
- 1행 시작 열: 제품명
- 1행 시작 열 + 2: 생산 기준값
- 각 제품 블록의 행 데이터:
  - 시작 열: 원료/영양제 이름
  - 시작 열 + 1: 기본 레시피 중량
  - 시작 열 + 2: 생산 기준값 기준 환산 중량
- 2~12행은 원료로 처리
- 13행 이후는 영양제/첨가제로 처리
- 이름이 비어 있거나 중량이 0/빈 값이면 건너뛴다.

## 제품명 자동 접두어

파일명 또는 시트명으로 동물 종류를 추론한다.

- `고양이`, `cat`, `kitty` 포함: `(고양이)` 접두어
- `강아지`, `개`, `dog`, `puppy` 포함: `(강아지)` 접두어
- 이미 `(고양이)`처럼 괄호 접두어가 있으면 중복으로 붙이지 않는다.

예:

- `레시피-고양이.xlsx`의 `치킨` -> `(고양이)치킨`
- `레시피-강아지.xlsx`의 `메추리` -> `(강아지)메추리`

## 생산단위 처리

- 각 제품의 첫 번째 원료를 생산단위 원료로 자동 지정한다.
- 생산단위 원료는 앱 내부에서 `isUnit: true`, `unit: "kg"`로 저장한다.
- 첫 번째 원료명이 `통닭`이면 `unitName: "마리"`를 자동 지정한다.
- 그 외 생산단위 원료의 `unitName`은 비워 둔다.

## 중복 처리

제품명 기준으로 중복을 판단한다.

- 기존 제품명과 같은 제품이 엑셀에 있으면 덮어쓴다.
- 기존에 없는 제품은 새로 추가한다.
- 가져오기 전에 브라우저 confirm으로 요약을 보여준다.
  - 엑셀에서 찾은 제품 수
  - 새로 추가될 제품 수
  - 덮어쓰기 될 제품 수

덮어쓰기 시 기존 제품의 `id`는 유지한다. 이로 인해 기존 선택 상태나 프리셋과의 연결이 최대한 유지된다.

## 저장

가져오기가 완료되면 즉시 `recipe_cost_utf8_v1` 로컬 저장소에 저장한다. 단가, 발주 프리셋, 발주 입력값은 별도 저장 구조를 유지하며 가져오기 과정에서 삭제하지 않는다.

## 제한 사항

- 현재는 첫 번째 시트만 읽는다.
- 현재는 샘플처럼 4열 단위 반복 구조만 지원한다.
- 단가 시트 자동 import는 아직 없다.
- 생산 기준값 열은 현재 표시/검증에는 쓰지 않고, 기본 레시피 중량만 앱 데이터로 저장한다.
- 엑셀 파싱 라이브러리는 CDN의 SheetJS를 사용하므로 인터넷 연결이 필요하다.
