# 레시피 원가 계산기 v2 스펙

## 목적

기존 단일 `index.html` 앱을 v2 데이터 모델로 분리해 원료/영양제 마스터, 제품, 단가, 결과 옵션, 발주 프리셋을 안정적으로 관리한다.

## 저장 구조

- v2 저장 키: `recipe_cost_v2_state`
- v2 스냅샷 키: `recipe_cost_v2_snapshots`
- v1 읽기 전용 키:
  - `recipe_cost_utf8_v1`
  - `recipe_cost_order_v1`

v2 최초 로드 시 v2 키가 없고 v1 키가 있으면 v1 데이터를 마이그레이션해 v2 키에 저장한다. v1 키는 삭제하지 않는다.

## v2 데이터 모델

- `ingredients`: 원료/영양제 마스터. 이름과 단가는 제품과 분리된다.
- `products`: 제품 본문. 제품명, 종, 생산단위 원료, 구성 원료를 가진다.
- `productOrder`: 제품 표시 순서.
- `prices`: `ingredientId` 기준 단가.
- `presets`: 발주 프리셋.
- `orderQuantities`: `presetId__ingredientId` 기준 발주 수량.
- `ui`: 선택 제품, 결과 옵션, 편집 중 제품, 활성 탭.

## 제품명/종 처리

- 제품명에는 `(고양이)`, `(강아지)` 접두어를 저장하지 않는다.
- 종은 `species: "cat" | "dog" | null`로 저장한다.
- 화면 표시 시 `getDisplayProductName()`이 접두어를 합성한다.

## 마이그레이션 규칙

- v1 제품의 `(고양이)`/`(강아지)` 접두어는 `species`로 분리한다.
- 같은 이름과 같은 kind의 원료/영양제는 하나의 마스터로 병합한다.
- v1 `row.id`는 v2 `ingredientId`로 매핑해 결과 옵션과 프리셋 생산단위를 보존한다.
- v1 단가에만 있고 레시피에는 없는 항목도 orphan ingredient로 보존한다.
- `recipe_cost_order_v1`의 `orderPresets`/`orderInputs`와 legacy `presets`/`orderData`를 모두 읽는다.

## 엑셀 일괄 등록

- 지원 파일: `.xlsx`, `.xls`
- SheetJS CDN을 사용한다.
- 첫 번째 시트만 읽는다.
- 제품은 4열 단위 블록으로 읽는다. 시작 열은 `A`, `E`, `I`, `M` 순서다.
- 1행 시작 열은 제품명이다.
- 2~12행은 원료, 13행 이후는 영양제로 처리한다.
- 이름이 비어 있거나 기본 중량이 0이면 건너뛴다.
- 파일명 또는 시트명에 `고양이`, `cat`, `kitty`가 있으면 `cat`으로, `강아지`, `개`, `dog`, `puppy`가 있으면 `dog`으로 추론한다.
- 제품명에 이미 `(고양이)`/`(강아지)`가 있으면 그 접두어를 우선한다.
- 첫 번째 원료는 생산단위 원료로 지정하고 단위는 `kg`로 저장한다.
- 첫 번째 원료명이 `통닭`이면 생산단위 이름을 `마리`로 지정한다.

## 중복 처리

엑셀 import는 `species + 제품명`을 기준으로 중복을 판단한다.

- 같은 제품이 있으면 기존 `product.id`를 유지하고 구성 원료만 덮어쓴다.
- 새 제품이면 제품을 추가한다.
- 기존 단가, 발주 프리셋, 선택 상태는 가능한 한 보존한다.
- 덮어쓰기 후 결과 옵션 또는 프리셋 생산단위가 사라진 원료를 가리키면 새 생산단위 원료로 보정한다.
